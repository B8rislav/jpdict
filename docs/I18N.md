# I18N

**Status: partially implemented. A module exists and is in active use; a formal D2 phase
(lint guards, `<html lang>` localisation, `generateMetadata`) is not yet landed. See
TASKS.md D2 for the planned work.**

## Current implementation

File: `src/shared/i18n/index.ts`

The module keeps the active locale in module-level state (not in a store). The
`$userProfile` store calls `setLocale(uiLocale)` on every profile update, so the active
locale always matches the user's preference.

### API

```ts
t(category: string, key: string): string
```

Looks up `dictionaries[locale][category][key]`. Falls back to Russian if the key is
missing in the active locale.

```ts
setLocale(locale: 'ru' | 'en'): void
```

Called by `src/stores/userProfile.ts` when `uiLocale` changes.

### Dictionaries

| File | Locale | Coverage |
|------|--------|---------|
| `src/shared/i18n/ru.json` | Russian | primary; all keys |
| `src/shared/i18n/en.json` | English | secondary; gaps fall back to Russian |

### Example usage

```ts
import { t } from '@/shared/i18n';
t('ui', 'nav_login')   // → "Войти" (ru) or "Log in" (en)
t('ui', 'lang_jp')     // → "Японский" / "Japanese"
```

## `<html lang>` attribute

`src/app/HtmlLangSync.tsx` is a Client Component mounted in the root layout. It reads
`$userProfile.selectedLanguage` and sets `document.documentElement.dataset.lang` to
`'jp'` or `'cn'`. This attribute is used by the CSS variable system to switch CJK fonts
(see STYLING.md), not for accessibility `lang` attribute. The `<html lang>` attribute
itself is not dynamically set — that is part of the D2 plan.

## Adding new strings

1. Add the key-value pair to `src/shared/i18n/ru.json` first (Russian is the source of truth).
2. Add the matching key to `src/shared/i18n/en.json`.
3. Call `t('category', 'key')` in the component.
4. D2.4 will add a lint guard to catch missing keys at CI time.
